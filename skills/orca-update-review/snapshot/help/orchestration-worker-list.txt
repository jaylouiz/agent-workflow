orca orchestration worker-list

Usage: orca orchestration worker-list [--run <run_id>] [--terminal-state <active|reclaimable|retained|release_pending|release_unknown|released>] [--include-remote] [--cursor <cursor>] [--limit <1-100>] [--json] [--full]

List supervised worker terminal resource accounting

Options:
  --help                 Show this help message
  --json                 Emit machine-readable JSON
  --pairing-code <code>  Run against a remote Orca server using an orca://pair?... code
  --environment <selector> Run against a saved paired Orca server (id or name), or `local` for this machine's own Orca over ORCA_ENVIRONMENT/ORCA_PAIRING_CODE; terminal handles belong to the server that issued them
  --run
  --terminal-state <state> Terminal accounting filter: active, reclaimable, retained, release_pending, release_unknown, or released
  --include-remote      Include connected-server worker observations
  --cursor <cursor>      Opaque page cursor copied from nextCursor
  --limit <n>            Maximum number of rows to return
  --full                 Print the full record Orca returned instead of the concise view

Notes:
  Terminal state is process accounting and is reported separately from Task status; a completed Task can still own a live terminal.
  A reclaimable worker with resource.autoReleaseAt is released automatically at that time unless it is reused with worker-start --terminal or kept open (worker-keep-open, worker-start --keep-open, or the user).
  Context-only Dispatches created by orchestration dispatch are included as unsupervised with terminal state retained.
  Returns at most 100 local rows, newest first, by default; --include-remote adds connected-server observations when the host supports fleet listing. Continue with the opaque nextCursor value unchanged.
  Without --run the list is scoped to the Run bound to the calling terminal, and to every Run when there is no binding; the receipt reports which in scope.source (flag, bound, or all).
