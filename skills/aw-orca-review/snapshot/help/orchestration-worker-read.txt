orca orchestration worker-read

Usage: orca orchestration worker-read --dispatch <dispatch_id> [--source <auto|transcript|terminal>] [--cursor <cursor>] [--limit <n>] [--json] [--full]

Read bounded output from one supervised worker

Options:
  --help                 Show this help message
  --json                 Emit machine-readable JSON
  --pairing-code <code>  Run against a remote Orca server using an orca://pair?... code
  --environment <selector> Run against a saved paired Orca server (id or name), or `local` for this machine's own Orca over ORCA_ENVIRONMENT/ORCA_PAIRING_CODE; terminal handles belong to the server that issued them
  --dispatch
  --source
  --cursor <cursor>      Opaque cursor returned by a previous worker-read page
  --limit <n>            Maximum number of rows to return
  --full                 Print the full record Orca returned instead of the concise view

Notes:
  The default auto source uses an exact hook-reported transcript when available and otherwise returns labeled terminal output.
  A Dispatch created by orchestration dispatch reads from its adopted terminal with worker status unsupervised.
  Output stays readable after the terminal is released, including an automatic release after worker_done.
  A returned cursor is pinned to the exact source; start a fresh read if Orca reports source_changed.
